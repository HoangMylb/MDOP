# MDOP — WEBSITE DESIGN & DEVELOPMENT BRIEF

## MAKE DREAMS. OWN PORSCHE.

**Project type:** Conversion Website / Automotive Commerce Experience  
**Project name:** MDOP  
**Working meaning:** Make Dreams. Own Porsche.  
**Primary subject:** Porsche vehicles and Porsche-inspired premium automotive shopping experience  
**Positioning:** High-conversion luxury automotive commerce design study  
**Project intent:** Portfolio / design / UX / frontend learning project. No real commercial transactions are required.

---

# 1. PROJECT OVERVIEW

MDOP is the conversion counterpart to YDAP.

YDAP asks:

> Can a website make someone feel desire?

MDOP asks:

> Can a website turn that desire into a confident buying action?

The site should combine:

- premium automotive art direction,
- high-end product presentation,
- clear model discovery,
- comparison,
- configuration,
- purchase-intent capture,
- test-drive / consultation lead capture,
- ownership reassurance,
- and conversion-focused UX.

The website exists primarily to create:

**ATTENTION → INTEREST → PRODUCT DISCOVERY → CONFIDENCE → INTENT → ACTION**

rather than stopping at attention and emotion.

The Porsche product remains visually desirable, but every important screen must help the user answer one of these questions:

1. What should I choose?
2. Why is this model right for me?
3. What is the difference?
4. What does it cost?
5. Can I personalize it?
6. What happens after I decide?
7. What should I do next?

---

# 2. PRIMARY BUSINESS OBJECTIVE

MDOP should simulate a premium direct-to-consumer automotive funnel.

Primary conversion goals:

1. Explore models.
2. Open a vehicle detail page.
3. Compare models.
4. Start configuration.
5. Save a configuration.
6. Request a consultation.
7. Book a test drive.
8. Check available inventory.
9. Begin a purchase/reservation flow.
10. Return to a saved vehicle.

The website must never sacrifice clarity for visual spectacle.

A beautiful composition that hides the next action is a failed conversion composition.

---

# 3. CORE CONVERSION PRINCIPLE

> **DESIRE OPENS THE FUNNEL. CLARITY CLOSES THE GAP.**

Premium conversion does not mean adding more buttons.

The experience should create this progression:

**DESIRE**

↓

**RELEVANCE**

↓

**UNDERSTANDING**

↓

**TRUST**

↓

**REDUCED FRICTION**

↓

**DECISION**

↓

**ACTION**

Every page should know which stage it serves.

---

# 5. CONVERSION HIERARCHY

Every important screen should have:

### PRIMARY ACTION

The single most important next step.

Examples:

- Explore models
- Configure
- Check availability
- Reserve
- Book a test drive

### SECONDARY ACTION

Useful but lower commitment.

Examples:

- Compare
- Save
- View details
- Download summary
- Contact advisor

### TERTIARY ACTION

Supporting exploration.

Examples:

- Learn more
- View gallery
- Read ownership information

Do not give every action equal visual weight.

---

# 6. HOMEPAGE PURPOSE

The homepage is not a cinematic exhibition.

Its job is to:

1. Create desire.
2. Establish Porsche product authority.
3. Help users enter the correct buying path quickly.
4. Surface the model range.
5. Explain meaningful differences.
6. Provide ownership reassurance.
7. drive users toward a high-intent action.

The homepage should feel premium without becoming a long brand film.

---

# 7. HOMEPAGE STRUCTURE

Approximately 8–10 high-value sections.

## SECTION 01 — Hero / Decision Entry

Full-bleed Porsche imagery.

Primary message should be concise.

Example direction:

# FIND THE PORSCHE  
# THAT MOVES YOU.

Primary CTA:

**Explore models**

Secondary CTA:

**Build your Porsche**

Optional high-intent utility:

**Available now**

The first viewport must show a real path forward.

---

## SECTION 02 — Model Families

Show major model families as visually strong product entries.

Possible families for the design study:

- 911
- Taycan
- Macan
- Cayenne
- Panamera
- 718

Each entry should show:

- model name,
- vehicle image,
- short positioning phrase,
- indicative starting-price field,
- body / use-case cue,
- primary CTA.

Do not invent real prices in the implementation.

Use verified project data or explicit demo labels.

---

## SECTION 03 — Find Your Porsche

A guided product finder.

Potential questions:

- Sports car, SUV, sedan or electric?
- Daily use or weekend performance?
- 2 seats or family practicality?
- Electric or combustion preference?
- Budget range?
- Performance priority or comfort priority?

The result should narrow the model set.

This is a conversion tool, not a quiz for entertainment.

---

## SECTION 04 — Featured Vehicle

One model receives a cinematic high-impact moment.

Possible content:

- strong hero image,
- 3–4 key attributes,
- short benefit-led copy,
- Configure CTA,
- View details CTA.

This is where MDOP can inherit some YDAP emotional craft without losing conversion focus.

---

## SECTION 05 — Compare

Introduce comparison early enough for undecided users.

Example:

**Choose your next Porsche. See the difference.**

Allow 2–3 models to be compared.

Key comparison dimensions:

- body type,
- seats,
- drivetrain,
- performance class,
- range / fuel type,
- cargo practicality,
- indicative pricing,
- availability.

Do not overload with engineering data.

---

## SECTION 06 — Available Now

Inventory preview.

Cards may be justified here because the user is scanning products.

Each vehicle card should support:

- image,
- exact model/variant,
- exterior color,
- key configuration,
- price field,
- location/status field,
- View vehicle,
- Reserve / Contact.

Cards must remain visually automotive, not generic ecommerce tiles.

---

## SECTION 07 — Ownership Confidence

Reduce purchase anxiety.

Potential topics:

- warranty,
- service,
- financing,
- delivery,
- trade-in,
- charging support for EVs,
- advisor assistance.

Keep the design calm and trustworthy.

This section exists to reduce friction before conversion.

---

## SECTION 08 — Social Proof / Proof of Product

Possible proof types:

- press recognition,
- verified owner stories,
- expert review excerpts,
- awards,
- engineering milestones.

For the design study, do not fabricate testimonials or claims.

Use clearly marked demo content until verified data is provided.

---

## SECTION 09 — Final Decision CTA

End with one strong decision.

Example:

# YOUR PORSCHE  
# STARTS HERE.

Primary:

**Build your Porsche**

Secondary:

**Talk to an advisor**

Do not end with five competing CTAs.

---

# 8. MODELS PAGE

Route:

`/models`

Purpose:

Help users understand and narrow the product range.

Required capabilities:

- strong visual model overview,
- body-type filtering,
- drivetrain filtering,
- lifestyle/use-case filtering,
- price-range filtering,
- compare selection,
- quick access to configuration,
- responsive mobile browsing.

Recommended presentation:

Large editorial model rows or image-led tiles.

Do not make it look like a supermarket product grid.

---

# 9. VEHICLE DETAIL PAGE

Suggested route:

`/models/[model]`

This is one of the most important conversion surfaces.

Recommended structure:

1. Product hero.
2. Core decision information.
3. Price / demo-price field.
4. Key attributes.
5. Configure CTA.
6. Availability CTA.
7. Gallery.
8. Performance / driving experience.
9. Interior / comfort.
10. Technology.
11. Practicality.
12. Ownership information.
13. Comparison prompt.
14. Sticky conversion CTA.
15. Final CTA.

The user should never have to scroll back to the top to act.

---

# 10. PRODUCT HERO

The hero should immediately answer:

- What vehicle is this?
- What does it look like?
- What is its role?
- What is the price position?
- What can I do next?

Possible layout:

Large vehicle image  
+ model identity  
+ short product statement  
+ starting-price field  
+ Configure  
+ Check availability

Avoid giant marketing copy that pushes the product and CTA below the fold.

---

# 11. CONFIGURATOR

Route:

`/configure/[model]`

The configurator is a core conversion experience.

Recommended stages:

1. Model / variant.
2. Exterior color.
3. Wheels.
4. Interior.
5. Packages / options.
6. Review.
7. Save / continue.
8. Contact / reserve.

Design behavior:

- vehicle remains highly visible,
- selected options are obvious,
- price summary remains accessible,
- progress is clear,
- backtracking is easy,
- changes feel immediate,
- mobile controls are redesigned rather than compressed.

Do not build a fake infinite option system.

Use a controlled demo data model.

---

# 12. COMPARISON EXPERIENCE

Route:

`/compare`

Support 2–3 vehicles.

Start with meaningful decision criteria.

Recommended order:

1. Visual identity.
2. Starting price.
3. Body/use case.
4. Seats/practicality.
5. Drivetrain.
6. Performance.
7. Efficiency/range.
8. Cargo.
9. Core features.
10. CTA per model.

Highlight meaningful differences.

Do not turn the page into a spreadsheet.

---

# 13. INVENTORY EXPERIENCE

Route:

`/inventory`

Purpose:

Serve high-intent users who want a vehicle now.

Filtering may include:

- model,
- variant,
- price,
- color,
- drivetrain,
- availability,
- location.

Results should prioritize:

**vehicle → price → availability → action**

not marketing prose.

---

# 14. LEAD CAPTURE

Lead forms should appear only when the user has context.

Potential conversion points:

- Book a test drive.
- Request consultation.
- Ask about availability.
- Reserve vehicle.
- Request finance information.
- Trade-in enquiry.

Keep forms short.

Recommended first-step fields:

- name,
- preferred contact method,
- email / phone,
- model of interest.

Ask additional questions only when they improve follow-up.

---

# 15. FORM UX

Required:

- clear field labels,
- inline validation,
- proper keyboard/input types,
- loading state,
- success state,
- error state,
- preservation of entered values,
- accessible error messaging.

Success state should explain exactly what happens next.

Do not end with:

> Thanks! Form submitted.

Instead:

> Request received. A Porsche advisor will contact you using your selected method.

For a non-commercial prototype, clearly label this as a simulated flow.

---

# 16. STICKY CONVERSION SYSTEM

Desktop:

A restrained sticky action bar may appear after the hero.

Possible content:

Model / price  
Configure  
Availability

Mobile:

A compact bottom action area may contain:

Primary CTA + one secondary action.

Do not cover important content.

---

# 17. NAVIGATION

Recommended top-level navigation:

- Models
- Configure
- Inventory
- Compare
- Ownership

Utility actions:

- Search
- Saved
- Account

Primary header CTA:

**Build your Porsche**

Header should feel premium but more functional than YDAP.

No interaction should hide key commerce destinations.

# 18. SEARCH

Search should support intent-based discovery.

Examples:

- 911
- electric SUV
- family
- available now
- under demo budget
- red vehicle

Search UI should favor product results over long content pages.

---

# 19. SAVED STATE

Users should be able to simulate saving:

- vehicles,
- comparisons,
- configurations.

State should persist locally for the prototype where practical.

Returning users should be able to resume quickly.

---

# 20. VISUAL DIRECTION

MDOP should feel:

- premium,
- precise,
- desirable,
- editorial,
- engineered,
- confident,
- calm,
- high-performance,
- purchase-ready.

Difference from YDAP:

YDAP = darkness, tension, reveal, memory.

MDOP = clarity, desirability, confidence, action.

MDOP may still use cinematic images and motion, but commerce clarity always wins.

---

# 21. COLOR SYSTEM

Use a Porsche-inspired premium system.

### Core dark

Near-black, not flat pure black everywhere.

Example direction:

`#0B0B0C`  
`#111214`

### Warm light

For content surfaces.

Example:

`#F5F3EE`

### Technical graphite

For secondary UI.

Example:

`#5C5F63`

### Performance red

Selective action / emphasis.

Example conceptual direction:

`#D5001C`

### Product color

Vehicle paint may become a temporary contextual accent.

Do not force one brand accent across every vehicle image.

---

# 22. TYPOGRAPHY

Two roles.

### Brand / Editorial Display

Used for:

- hero statements,
- campaign moments,
- model names,
- high-impact transitions.

### Product / Interface Type

Used for:

- price,
- specifications,
- filters,
- forms,
- configurator controls,
- availability,
- ownership information.

The interface type must prioritize readability.

Do not use expressive display typography for transactional UI.

---

# 23. IMAGERY

Product photography is critical.

Preferred:

- official-quality Porsche vehicle photography,
- studio vehicle imagery,
- full exterior views,
- detail views,
- interior views,
- motion imagery,
- consistent color grading.

For this design study, project assets may intentionally use Porsche logos and Porsche vehicle imagery as direct visual material.

Prepare image variants for:

- desktop,
- tablet,
- mobile,
- cards/listing,
- PDP hero,
- comparison,
- configurator.

Never stretch one crop across every context.

---

# 24. LOGO & BRAND MARKS

MDOP may use Porsche visual assets in the prototype where the project author intentionally wants direct brand-study fidelity.

Rules for the design system:

- use high-quality vector/raster assets,
- preserve logo proportions,
- never distort the crest,
- keep sufficient whitespace,
- do not decorate the logo with effects,
- do not use the crest as a repeated background pattern,
- keep MDOP as the project/product-experience name.

The interface should feel Porsche-grade, not like a logo pasted onto a generic template.

---

# 25. PRODUCT DATA POLICY

Never invent precise:

- prices,
- horsepower,
- range,
- acceleration,
- dimensions,
- financing rates,
- delivery dates,
- availability.

Create structured demo data with one of these states:

- `verified`
- `demo`
- `unknown`

UI must be able to distinguish demo content during development.

---

# 26. MOTION

Target:

**M3–M4 — Premium Product Motion**

Allowed:

- image reveal,
- smooth model transitions,
- color/configuration transitions,
- sticky image behavior,
- restrained parallax,
- comparison transitions,
- microinteractions,
- page transitions.

Avoid:

- long unskippable cinematic sequences,
- animation that delays product information,
- bouncing buttons,
- random particles,
- excessive WebGL,
- scroll-jacking.

Motion should accelerate decision-making, not postpone it.

---

# 27. RESPONSIVE STRATEGY

Desktop, laptop, tablet and mobile all require intentional design.

Mobile priorities:

1. Product image.
2. Product name.
3. Price / positioning.
4. Primary CTA.
5. Key attributes.
6. Easy filters.
7. Easy configurator controls.

Avoid:

- desktop comparison tables squeezed into mobile,
- tiny filters,
- hover-only behavior,
- full-screen effects that trap scrolling.

---

# 28. ACCESSIBILITY

Required:

- semantic HTML,
- keyboard navigation,
- visible focus states,
- sufficient contrast,
- form labels,
- accessible validation,
- reduced motion,
- alt text,
- screen-reader-friendly price/state messaging,
- accessible dialog behavior.

Conversion UX that excludes users is not strong conversion UX.

---

# 29. PERFORMANCE

Premium means immediate.

Targets:

- optimize hero media,
- responsive images,
- AVIF/WebP where appropriate,
- lazy-load non-critical media,
- avoid oversized JS,
- code split configurator features,
- preload only truly critical assets,
- use poster frames for video,
- no unnecessary Three.js.

Product browsing must remain fast on mobile.

# 32. CONVERSION METRICS

Primary:

- model detail view rate,
- configure-start rate,
- compare usage,
- inventory detail rate,
- lead-form start rate,
- lead-form completion rate,
- reservation-start rate.

Secondary:

- save rate,
- return rate,

---

# 33. THINGS AI MUST NOT DO

Do not:

1. Turn MDOP into YDAP with extra buttons.
2. Hide product information behind cinematic effects.
3. Put five CTAs in every section.
4. Use generic SaaS cards.
5. Use bento grids by default.
6. Create fake Porsche technical data.
7. Create fake reviews.
8. Create fake financing terms.
9. Use fake scarcity.
10. Add countdown timers.
11. Use manipulative dark patterns.
12. Preselect paid options without clarity.
13. Make forms unnecessarily long.
14. Disable back navigation in funnels.
15. Force account creation before exploration.
16. Autoplay aggressive sound.
17. Use motion that blocks action.
18. Treat mobile as desktop scaled down.
19. Use low-quality car imagery.
20. Let UI compete with the vehicle.

# 34. QUALITY BAR

Evaluate every important screen on:

### Desire
Does the product still feel aspirational?

### Clarity
Can the user understand what is being offered?

### Relevance
Can the user identify the right model?

### Confidence
Does the interface reduce uncertainty?

### Friction
Is the next action easy?

### Hierarchy
Is one action clearly primary?

### Product presentation
Does the car remain visually dominant?

### Mobile
Can the journey be completed comfortably on mobile?

### Performance
Does the product experience feel immediate?

### Conversion
Does the design move intent forward?

# 35. DEVELOPMENT PRIORITY

## P0 — PRODUCT & CONVERSION MODEL

Define:

- model data,
- user journeys,
- conversion actions,
- funnel states,
- demo vs verified data.

## P1 — DESIGN SYSTEM

Define:

- typography,
- color,
- spacing,
- product imagery,
- CTA hierarchy,
- cards/listing system,
- forms,
- motion tokens.

## P2 — HOMEPAGE + MODELS

Build the primary discovery path.

## P3 — VEHICLE DETAIL

Build the core product decision surface.

## P4 — CONFIGURATOR + COMPARE

Build the highest-value interactive conversion tools.

## P5 — INVENTORY + LEAD FLOW

Build high-intent paths.

## P6 — RESPONSIVE + ACCESSIBILITY

Recompose for mobile and harden interaction.

## P7 — PERFORMANCE + POLISH

Optimize assets, motion, state and consistency.

- [ ] User can save a vehicle/configuration.
