## Implementation integrity verdict

**Pass, with repairable gaps.** The route retains the product-specific Drive Line sequence, status-aware product language, real model/configure/inventory/compare destinations, and no fabricated vehicle data. The detector reports no shortcut patterns. The remaining issues are system-quality defects rather than a generic-product drift: keyboard focus transfer, semantic grouping, status contrast, resource delivery, and development quality gates.

## Findings

### P1 — Skip navigation does not move keyboard focus

- **Location:** `app/page.tsx:45,49`; `app/harden.css:1`.
- **Category:** Accessibility / semantics.
- **Impact:** `Bỏ qua điều hướng` targets `#content`, a plain `div` without `tabindex`. It scrolls visually but leaves keyboard focus on the skip link, so keyboard users do not enter the main content reliably.
- **Standard:** WCAG 2.4.1 Bypass Blocks; WCAG 2.4.3 Focus Order.
- **Recommendation:** Make the document header a sibling of `<main>`, give the main target `id="content" tabIndex={-1}`, and ensure the skip link targets that focusable landmark.
- **Suggested command:** `$impeccable harden`.

### P1 — Finder choices are not semantically grouped with their question

- **Location:** `app/page.tsx:50`.
- **Category:** Accessibility / interaction states.
- **Impact:** The question is an independent `<h3>` followed by generic buttons. A screen-reader user cannot programmatically discover that all three buttons answer that question, and the changing container’s `aria-live="polite"` can announce more than the meaningful change.
- **Standard:** WCAG 1.3.1 Info and Relationships; WCAG 4.1.2 Name, Role, Value.
- **Recommendation:** Use a `fieldset`/`legend` or a labelled `role="group"`, expose step progress with a proper label, and narrow the live region to the result/status message.
- **Suggested command:** `$impeccable harden`.

### P1 — Small status labels do not have a guaranteed AA contrast ratio on light surfaces

- **Location:** `.status` in `app/globals.css:1`, overridden in `app/typeset.css:27`; used in the family/featured/inventory/ownership areas.
- **Category:** Accessibility / theming.
- **Impact:** The inherited muted `#666` on `#f4f1eb`, then opacity `.86`, produces a rendered light gray near 3.8:1 rather than the 4.5:1 required for small text. `Bản minh hoạ` is conversion-critical disclosure and must remain legible.
- **Standard:** WCAG 1.4.3 Contrast (Minimum).
- **Recommendation:** Use an explicit high-contrast status foreground per surface and remove opacity as the primary hierarchy mechanism; retain the visible text status.
- **Suggested command:** `$impeccable colorize`.

### P1 — Below-fold vehicle media bypasses image optimisation

- **Location:** `app/option-three-assets.css:2-7`, `app/globals.css:1` (`.family-photo`).
- **Category:** Performance / responsive delivery.
- **Impact:** Six family lanes use CSS `background-image` PNGs, so they do not get `next/image` sizing, lazy loading, responsive source selection, or modern image conversion. The image directory is 8.9 MB, and the LCP source PNG alone is 1.4 MB.
- **Recommendation:** Move semantic family vehicle media to `next/image` (or a responsive `<picture>` strategy) with accurate sizes and lazy loading; create responsive WebP/AVIF derivatives where appropriate.
- **Suggested command:** `$impeccable optimize`.

### P2 — Corrupted or unavailable localStorage can stop state hydration

- **Location:** `app/page.tsx:16-18`.
- **Category:** Implementation integrity / resilience.
- **Impact:** `JSON.parse(localStorage.getItem(...))` has no validation or recovery. A malformed persisted value, privacy restriction, or storage exception can throw in the effect and leave compare/saved state broken.
- **Recommendation:** Add safe parse/shape validation and guarded storage reads/writes; fall back to an empty state and announce only meaningful recovery.
- **Suggested command:** `$impeccable harden`.

### P2 — The homepage unnecessarily hydrates every static section

- **Location:** `app/page.tsx:1-57`.
- **Category:** Performance.
- **Impact:** The whole long homepage is a single client component because Finder, storage, and CTA state live at route level. Static hero, range, inventory, ownership, proof and final sections are included in the client boundary.
- **Recommendation:** Isolate the interactive Finder/compare/save/mobile-CTA island(s) and render static editorial sections on the server without changing the Drive Line order.
- **Suggested command:** `$impeccable optimize`.

### P2 — Lint script is not a working verification gate

- **Location:** `package.json` (`"lint": "next lint"`).
- **Category:** Implementation integrity / developer experience.
- **Impact:** `npm run lint` exits with `Invalid project directory .../lint` on Next 16. Regression checks therefore rely only on build and the detector.
- **Recommendation:** Replace with a supported ESLint invocation/configuration, or remove the misleading script until configured.
- **Suggested command:** `$impeccable harden`.

### P2 — Theme tokens and direct colours are mixed across style passes

- **Location:** `app/globals.css`, `app/harden.css`, `app/motion.css`, `app/adapt.css`.
- **Category:** Theming / consistency.
- **Impact:** Core tokens exist, but 17+ direct hex/RGBA values are distributed across the cascade. This makes contrast fixes and future contextual paint accents harder to govern consistently.
- **Recommendation:** Consolidate semantic surface/text/border/status tokens first; preserve the current dark/warm visual direction rather than introducing a generic theme switch.
- **Suggested command:** `$impeccable colorize`.

### P3 — Live browser/device evidence is still missing

- **Location:** Audit environment, not a code defect.
- **Category:** Responsive verification.
- **Impact:** 360/390/430/768/1024 visual clipping, crop quality and sticky focus overlap cannot be certified from source alone.
- **Recommendation:** Run the existing page against a local/browser-capable environment and test keyboard plus reduced-motion at the named widths.
- **Suggested command:** `$impeccable audit`.

## Patterns and positive findings

### Patterns

- The CSS cascade currently spans multiple pass files with direct colour declarations, which causes token drift and makes a contrast fix non-local.
- Interactive state is thoughtfully implemented, but semantic and resilience handling has not kept pace with the UI refinement.

### Positive findings

- One H1 and a consistent H2/H3 section hierarchy are present.
- Links and buttons are used appropriately for their destinations/actions; no clickable `div`/`span` pattern was found.
- The native mobile `<details>` menu has a visible focus style and uses normal keyboard semantics.
- Model, compare, save and Finder state use visible text plus `aria-pressed`/live feedback rather than colour alone.
- Motion has a reduced-motion path and does not gate CTA availability.
- CTA routes, image alts and prototype/data-status language are coherent; no price, performance, availability, testimonial or scarcity claim is fabricated.
- Build passes and the Impeccable detector returns `[]`.

## Recommended action order

1. **[P1] `$impeccable harden`** — repair skip-focus semantics, Finder grouping/live-region semantics and resilient persistence; restore a functional lint gate.
2. **[P1] `$impeccable colorize`** — establish status/surface tokens and bring illustrative/unknown labels to AA contrast.
3. **[P1/P2] `$impeccable optimize`** — replace CSS background vehicle media with responsive optimised delivery and split static content from the client boundary.
4. **[P3] `$impeccable audit`** — rerun in a browser-capable environment at the required device widths after fixes.
5. **[P2] `$impeccable polish`** — only after the above systemic fixes are verified.
